# Data1 locking provenance and execution constraints

## What is locked from Data1 and how

| Object | Locking procedure | Where in code |
|---|---|---|
| Predictor selection | 13-pass leave-one-pass-out (LOPO) on Data1; deep seeds averaged within fold before the 13-fold mean/SD/SE; one-SE rule | `code/model_lopo.py`, `code/model_lopo_data.py` |
| Thickness predictor | GRU, one-update-ahead, 8-update input window (frozen weights) | `models/final_thickness_model.pt` |
| PID inner lock | Complete 1050-candidate grid executed through the canonical PID replay; each pass score is the arithmetic mean of the three channelwise normalized RMS values and the grid score is the equal mean of the 13 Data1 pass scores | `code/run_pid_selection_audit.py`; `results/pid_full_grid.csv`; `results/pid_selection_audit.json` |
| Flatness envelope | Phase-specific 2.5th/97.5th percentiles of the Data1 **recorded** normalized flatness error | `code/protocol.py: build_quantile_envelope` |
| Pass scales | Six scales computed passwise on Data1, stored in a 13-pass catalogue, then assigned by nearest entry/exit-gauge recipe using metadata only | `config/data1_scale_lock.json`; `code/scale_lock.py` |
| Innovation gain and response law | Versioned engineering settings held fixed within the released replay; not fitted causal coefficients | `controller_lock` / `controller_replay.py` |

The C2 / OC-PID / C7 family gains (0.64 / 0.48 / 0.76), the shares (ff 0.42, mpc 0.14), the fixed blend 0.10/0.90, the output weights [5.5, 6.0, 5.5], the penalty diag(16, 20, 18) and the policy-specific outer slew scales (0.60 / 0.95 / 0.80 / 0.80) are **versioned engineering design values** recorded in `config/controller_lock.json` and `config/selected_controller_configs.json`. This package does not claim that those constants were selected by a released optimization search, nor does it reconstruct a separate historical search record for them. They are frozen before the released Data2 rerun and are not modified from Data2 results; this establishes reproducibility of the frozen comparison, not global optimality or preregistration of the earlier engineering design. The complete Data1 grid applies only to the common inner PID multipliers and internal PID saturation scale. During candidate scoring, the released PID configuration is otherwise unchanged: gain scale 1.20, the canonical raw-measurement path with zero nominal synthetic measurement noise, pass-indexed segment-start initialization, the segmented archived-update timebase, amplitude bound $\pm0.55$, and outer move vector $[0.065,0.052,0.065]\times0.60$ converted with the 0.50-s reference and hard-step factor 2. Candidate `move_limit_scale` never rescales that outer projection.

## Executed implementation constraints

Every replay-dependent number, table and figure in this package was generated by `code/run_pipeline.py` under the following constraints:

1. **Causal measurement playback** — the local-median residual added to the controller measurement uses a segment-local trailing window only (`controller_replay.py`); no future row or prior segment enters the controller input. Canonical synthetic measurement noise is zero. The measurement model is documented as Eq. (S6).
2. **Shared stochastic settings** — the replay seed depends only on the pass index, so all policies share the same segment-start realization for a given pass. When an explicit measurement-noise sensitivity is run, policies within that scenario also share the same noise realization. Paired policy differences therefore use matched stochastic settings. A global-seed stability check is included (`results/seed_sensitivity_summary.csv`).
3. **C2 executes without the EKF observer**, matching Table 2 (`use_filter=false` in every C2 configuration).
4. **Segment discipline** — the locked predictor bank builds GRU input windows only when the window and the target row lie inside one segment (identical to the training rule), and the innovation extraction resets the hidden state at every segment boundary, mirroring the replay loop.
5. **Forward fill only** — missing rows are never completed from future rows (`real_process_data.py`, `model_lopo.py`, `controller_replay.py`).
6. **Strict upper-tail CVaR** — `tail_mean` returns the mean of the largest 5% of excess values.
7. **LinearARX baseline** uses a non-duplicated regressor design matrix.
8. **Sensitivity configurations** are generated from the canonical lock (`code/build_sensitivity_configs.py`), so the response-family, amplitude, anti-windup, numerical state-guardrail, rate and strict C7 NoMPC/NoBlend studies perturb the exact canonical policy (including its predictor bank and filter flags).
9. **Source-sequence relocking** (`code/run_relocking.py`) keeps the frozen Data1 GRU predictor in every omission fold and re-selects only the PID outer slew scale from {0.60, 0.80} on the retained sources, isolating the source-omission effect on the controller lock.
10. `config/model_selection.json` carries the one-SE threshold 0.869464 matching the LOPO summary.

The Data1-derived objects (GRU weights, predictor LOPO summary, equal-pass PID grid, reference envelope and six-scale catalogue) are not re-estimated from Data2. The PID-grid loader is restricted at the batch-I/O boundary to batches I, IV and VII and asserts the exact 13-pass Data1 identity set before scoring, so it does not open Data2 response files and then filter them after loading. The nominal innovation gain and response coefficients are engineering settings rather than estimated Data1 objects.

## Data availability

Raw production records are proprietary and are not included. On an authorized machine where the 26 raw pass CSV files are available, the pipeline locates them recursively by the SHA256 values in the de-identified archive map; original folder and file names are not required. Every replay-dependent result is reproduced by:

```powershell
py -3.14 code/run_pipeline.py --fresh --batch-root "<BATCH_ROOT>"
```

The pipeline first checks the Data1 scale catalogue and recomputes the complete PID candidate grid. It then runs the canonical replay, seven implementation-sensitivity sweeps, the Data1 sweep, the expanded four-batch / repeat-sequence / leave-one-batch-out / fixed-0.50-s audits, source-sequence relocking, the 20-scenario stress matrix, the local OPC UA loopback, the command audit, corridor and fault diagnostics, the appendix audit, the global-seed check, and finally assembles `results/`, figures and `MANIFEST_SHA256.csv`. `verify_results.py` audits hashes, scale provenance, time-source counts, state-guardrail counts, corridor identity and cross-table anchors offline.
