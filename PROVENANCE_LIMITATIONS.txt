Release integrity and verification scope

Release files

MANIFEST_SHA256.csv identifies the current distributed files by relative path,
byte count and SHA256. It covers every package file except itself. Use the fixed
GitHub commit accompanying the manuscript to identify the submission version.

Diagnostic receipts

results/farch_forward_audit.json records the source versions registered for its
individual diagnostic run. Those source versions are retained in the authors'
source archive. Its dependency_sha256 entries are run-specific source identifiers;
MANIFEST_SHA256.csv identifies the files in this distributed release. These two
records have distinct scopes and are not interchangeable. Diagnostic results
must be interpreted under the assumptions and source versions of their own run.

Frozen-weight replay and training

The replay pipeline loads models/final_thickness_model.pt. It does not repeat
the original predictor fitting or reconstruct model selection. As documented in
TRAINING_AUDIT.md, the original update count, seed, device, optimizer settings,
training curves and per-fold/per-seed score rows are not fully available.
Checkpoint metadata and published aggregate scores support consistency checks,
rather than reconstruction of the historical fit. Instrumented training-script
defaults describe a new experiment, rather than the frozen checkpoint's history.

Data access and verification

Raw proprietary production records and production-derived row trajectories are
confidential. Full replay requires authorized access to all 26 input CSV files
matching data_map/production_batch_map.csv, in a separate private working copy.
Generated row trajectories remain confidential.

Offline checks verify file identities, selected published calculations and tested
implementation contracts. They do not reconstruct every result from production
records, reproduce historical training or validate the emulator against a
physical mill. Farch is a rolling-origin forward-discrepancy diagnostic under an
assumed replay law; response-family, projection, fault and local OPC UA tests are
sensitivity or integration screens. The evidence is archived-data replay.
